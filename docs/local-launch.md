# Локальный запуск MusicStream и Prowlarr

Из корня проекта в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

Это меняет политику выполнения только для дочернего процесса PowerShell.
Глобальные настройки Windows не меняются. Скрипт запускает Prowlarr на
`http://127.0.0.1:18746`, затем MusicStream на `http://127.0.0.1:8000/app`.
Если сервис уже работает и отвечает, новая копия не запускается. Занятый
чужим сервисом порт вызывает понятную ошибку.

Prowlarr установлен отдельно от репозитория в
`%LOCALAPPDATA%\MusicStream\Prowlarr`. Его исполняемый файл находится в
`app\Prowlarr\Prowlarr.exe`, а действующая база — в `data\prowlarr.db`.
`start-prowlarr.ps1` всегда передаёт именно эту папку `data` через `-data`.
Перед запуском он проверяет сохранённые `BindAddress=127.0.0.1` и
`Port=18746` в `data\config.xml`. Изменение этих значений в конфигурации
остановит скрипт с ошибкой. У работающего процесса дополнительно проверяется
`appData` через локальный API: копия, запущенная без нужного `-data`, не будет
принята за действующую базу. API-ключ и пароль в скриптах не хранятся;
имеющийся ключ читается из локального `config.xml` только в памяти процесса.

Резервная копия базы перед переносом:
`%LOCALAPPDATA%\MusicStream\Prowlarr-backups\data-before-move-20261114-114755.zip`.
Она содержит `config.xml` и `prowlarr.db` и остаётся вне Git. Не публикуйте
этот архив: он содержит локальные секреты Prowlarr.

Общий скрипт по умолчанию запускает MusicStream без экспериментального
торрент-режима, даже если такие переменные присутствуют в текущей оболочке.
Для явно настроенного экспериментального запуска можно передать
`-EnableExperimentalTorrent`; тогда действуют уже заданные переменные
окружения. `uv` используется, когда доступен в `PATH`. Иначе запускается
`uvicorn` из существующей `.venv`, созданной `uv`; новые пакеты не
устанавливаются.

Проверено после переноса: Prowlarr отвечает на `/ping`, его API показывает
включённый индексатор NoNaMe Club (ID 1), а MusicStream отвечает на `/health`.
Оба действующих сервиса слушают только `127.0.0.1`. Запуск общей команды
повторно не создаёт дубликаты. Отдельный пробный запуск MusicStream на
временном локальном порту подтвердил, что скрипт запускает приложение и
оставляет экспериментальный маршрут выключенным по умолчанию; пробный
процесс был остановлен. Занятый другим HTTP-сервисом порт вызывает ошибку.
