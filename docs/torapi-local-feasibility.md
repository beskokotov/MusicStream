# Локальный TorAPI и RuTracker: проверка 13 ноября 2026 года

## Результат

Живые поисковые метаданные RuTracker получить не удалось. Исходный TorAPI не запускался: его запросы поиска и деталей отправляют встроенный cookie чужой сессии, а сервер по умолчанию слушает все интерфейсы. Пробные HEAD-запросы без cookie к `rutracker.org/forum/tracker.php`, `rutracker.net/forum/tracker.php` и `feed.rutracker.cc/atom/f/428.atom` завершились тайм-аутом DNS до соединения. Поэтому нельзя утверждать, что поиск и детали работают без учётной записи, либо проверить условия сайта из этой среды. Публичные экземпляры ранее ответили `402 DEPLOYMENT_DISABLED`.

## Устройство локального запуска

- [README TorAPI](https://github.com/Lifailon/TorAPI/blob/main/README.md) предлагает Node.js/npm (`npm install`, `npm start`) или Docker. [package.json](https://github.com/Lifailon/TorAPI/blob/main/package.json) указывает Express, Axios, Cheerio, iconv-lite и другие пакеты; отдельной базы данных нет. [`.env`](https://github.com/Lifailon/TorAPI/blob/main/.env) содержит порт и настройки прокси. `USERNAME`/`PASSWORD` — данные **прокси**, не RuTracker.
- В [main.js](https://github.com/Lifailon/TorAPI/blob/main/main.js) поиск делает GET `tracker.php?nm=...&f=...&start=...`, затем парсит HTML в Windows-1251. Детали делают GET `viewtopic.php?t=...` и POST `viewtorrent.php` для списка файлов. Оба потока используют `headers_RuTracker` со встроенным `bb_session`. Вариант Puppeteer также содержит этот cookie, хотя отключён флагом.
- `web.listen(port)` не задаёт `127.0.0.1`; [docker-compose.yml](https://github.com/Lifailon/TorAPI/blob/main/docker-compose.yml) публикует порт на всех интерфейсах. Без локальной правки исходника или отдельного ограничения привязки запуск не отвечает требованию «только 127.0.0.1».
- README утверждает, что регистрация нужна лишь для прямого `.torrent`, но код не проверяет гостевой режим. Встроенный cookie нельзя использовать как доказательство работы без авторизации. Конфигурации для собственной учётной записи RuTracker или официального токена TorAPI не предоставляет.

## Доступ и допустимая альтернатива

Официальные правила RuTracker об автоматизированном поиске и публичный поисковый API подтвердить не удалось: сайт и официальный feed недоступны по DNS из текущей среды. [Исходник TorAPI](https://github.com/Lifailon/TorAPI/blob/main/main.js) указывает на `https://feed.rutracker.cc/atom/f/<category>.atom` как на канал категорий; его фактический ответ и разрешённые условия использования также не проверены. Feed даёт новые публикации категории, но не полноценный запрос по исполнителю/альбому.

Если для поиска требуется учётная запись, пользователь должен войти через штатную страницу RuTracker и принять условия сайта. TorAPI не имеет механизма передачи своей сессии; его потребуется отдельно разработать и проверить на соответствие правилам источника. Пароль в код, параметры командной строки или репозиторий помещать нельзя. До такой проверки поддерживаемый в MusicStream путь — явный импорт пользователем разрешённого `.torrent` или magnet и локальные тестовые раздачи; при доступном и разрешённом Atom можно рассмотреть фильтрацию его записей по названию.

## Совместимость и следующий шаг

Существующий `TorApiDiscoveryProvider` уже принимает документированную форму JSON поиска и деталей через настраиваемый `base_url`, но живой ответ локального сервера проверить не удалось. Четыре локальных теста сохранённых ответов и синтетического торрента прошли; музыкальные файлы из сети не загружались.

После восстановления обычного доступа к RuTracker и подтверждения правил: проверить гостевой поиск и feed без cookie ограниченным числом запросов; при необходимости разработать личную авторизацию с безопасным хранением сессии; удалить встроенные сессии из собственной локальной копии TorAPI и привязать сервер к `127.0.0.1`; проверить реальные JSON ответы и только затем подключать discovery к Source Manager. Установка TorAPI, изменение Source Manager, TorrentSessionManager и интерфейса в этой проверке не выполнялись.
