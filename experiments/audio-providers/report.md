# Эксперимент: прямые аудио-API

Проверка выполнена 14 ноября 2026 года. Эталон — 13 конкретных записей из ответа работающего Deezer-поиска MusicStream; их ID, альбомы, длительности и версии сохранены в [tracks.json](tracks.json). Работающий MusicStream на порту 8000 использовался только для чтения метаданных. Prowlarr, BitTorrent, Auto Play и настройки системы не менялись.

## Метод

- Audius: официальный `GET /v1/tracks/search`, до 25 результатов на запрос, без учётных данных. Сопоставлялись исполнитель, название, версия, длительность (допуск 8 с) и альбом, когда он есть в ответе. Чужие загрузки, каверы, ремиксы, live, edit и превью не принимались за оригинал. [Документация Audius](https://docs.audius.co/api/).
- Jamendo: официальный `GET /v3.0/tracks` требует `client_id`; `audio` и `/v3.0/tracks/file?action=stream` предназначены для потока. Публичный тестовый `client_id`, указанный в [документации авторизации](https://developer.jamendo.com/v3.0/authentication), в живом ответе вернул код 11: тестовое приложение приостановлено. Рабочего зарегистрированного `client_id` нет. Поэтому отсутствие записей Jamendo **не проверено**; статус `AUTH_REQUIRED`. [Поиск](https://developer.jamendo.com/v3.0/tracks), [потоковый метод](https://developer.jamendo.com/v3.0/tracks/file).
- SoundCloud: официальные поиск и streaming API требуют зарегистрированное приложение. Для публичных ресурсов описан OAuth 2.1 Client Credentials с `client_id` и секретом; пользовательский Authorization Code требует PKCE. Ни приложения, ни токена в текущем процессе нет. Доступ `playable` означает полный поток, `preview` — только фрагмент, `blocked` — отсутствие потока. Статус всех записей `AUTH_REQUIRED`, а не `NOT_FOUND`. [Официальное руководство](https://developers.soundcloud.com/docs/api/).
- При найденной точной записи скрипт допускает лишь официальный поток и редирект с официального узла на документированное хранилище OpenAudio. Запрашиваются `bytes=0-4095` и `bytes=-4096`, читаются максимум 8 КиБ суммарно, соединения закрываются. `STREAM_OK` требует `206`, аудио MIME, сигнатуру начальных данных, общий размер в `Content-Range`, совместимый с полной длительностью, и доступность конца того же ресурса. Один `200` или HTML успехом не считается. [Документация OpenAudio о Cloudflare R2](https://docs.openaudio.org/tutorials/run-a-node/).

`NOT_FOUND` означает нулевой ответ точечного поиска, а не доказанное отсутствие во всём каталоге. `WRONG_VERSION` означает, что поиск вернул кандидатов, но ни один не прошёл проверку исполнителя, названия, длительности и версии. Поиск не является исчерпывающим аудитом каталога.

## Контроль доступности Audius

Чтобы отделить доступность потокового API от совпадения с Deezer, отдельно проверена одна доступная запись из официального `GET /v1/tracks/trending`. Её метаданные сообщили `is_streamable=true` и отсутствие gate. Официальный stream endpoint направил запрос через узел Audius на хранилище OpenAudio R2: получены **HTTP 206**, `audio/mpeg`, MP3-сигнатура, `Content-Range` с размером, соответствующим полной заявленной длительности, и **4096 первых байтов за 1,46 с**. Отдельный запрос последних 4096 байтов того же ресурса тоже дал `206`. Всего прочитано не более 8 КиБ. Предыдущие замеры начала составляли 1,14 и 2,09 с. Последний результат сохранён в [control.json](control.json) без ID записи и временного URL. Это подтверждает техническую возможность полного потока Audius для контрольной записи, но не любой записи из списка Deezer.

## Вывод для MusicStream

1. **Кто реально отдал аудио:** Audius, на контрольной записи из собственного каталога. Для 13 требуемых оригиналов поток не подтверждён. Jamendo и SoundCloud не удалось проверить без действующих учётных данных.
2. **Покрытие:** подтверждённое покрытие целевого набора — 0/13 у Audius. Процент Jamendo и SoundCloud неизвестен; нулём их каталог оценивать нельзя.
3. **Скорость:** 1,14–2,09 с до первых байтов контрольного Audius MP3 в трёх прогонах. Для целевых записей измерить время нельзя, поскольку точный поток не найден или доступ к API отсутствует.
4. **Совместимость:** подтверждённый Audius MP3 и HTTP Range технически совместимы с существующим HTML-аудиоплеером. Потребовались бы отдельный адаптер официального API, проверка записи и управление редиректами; переписывать работающий BitTorrent-транспорт не требуется. Для Jamendo форматы MP3/FLAC заявлены документацией, но живой поток не проверен. Для SoundCloud нужны OAuth, проверка `access`, поддерживаемый браузером формат транскодирования и соблюдение требований к атрибуции [из официального руководства](https://developers.soundcloud.com/docs/api/).
5. **Ограничения:** точное совпадение оригинала по Deezer у Audius не обнаружено; публичный тестовый Jamendo-клиент приостановлен; SoundCloud требует регистрации и OAuth, а часть записей может быть `preview`, `blocked` или ограничена регионом. Никакого вывода о геоблокировке конкретной записи без авторизованного запроса не делалось.

Интеграция не выполнялась. Повторяемый код точечных запросов — [probe.py](probe.py) и [control.py](control.py); обезличенные статусы — [results.json](results.json). Скрипты не сохраняют токены или прямые временные ссылки, не скачивают композиции целиком.
